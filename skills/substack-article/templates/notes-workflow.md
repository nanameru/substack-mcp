# Notes（短文ポスト）ワークフロー

Substack の **Notes** は X / Threads 風の短文 SNS 機能。Skill から `mcp__substack-mcp__post_note` で投稿できる。

## 記事との違い（重要）

| | Post（長文記事） | Note |
|---|---|---|
| タイトル / サブタイトル | あり | なし |
| 購読者へのメール配信 | 配信 OFF にも切替可能 | **配信されない** |
| 出版物（Publication）アーカイブ | 残る | 残らない（Notes フィードのみ） |
| 文字数 | 制限ほぼなし | 〜 4000 字（長文も書けるが Twitter 程度が標準） |
| 露出経路 | メール + Web + アプリ | **Substack 全体の Notes フィード**（Cross-publication） |
| 用途 | 主力コンテンツ | 日常的な接点・拡散・コミュニケーション |

→ Notes は **短い・気軽・頻繁** が基本。長文記事の合間に挟むことで、フォロワーとの日常的な接点をつくる。

## ツール

```
mcp__substack-mcp__post_note(text="...")
```

引数：
- `text`：本文プレーンテキスト。`\n\n` で段落区切り、`\n` でソフト改行（同一段落内の改行）。

戻り値：
- `note_id`：Note の ID
- `url`：`https://substack.com/note/c-<id>` 形式の公開 URL
- `raw`：API の生レスポンス（user_id・publication 情報など）

## 投稿パターン（記事ジャンル別）

ユーザーが「Notes 出して」と言ったとき、AI が自動でタイプを判定して提案する。

### 1. 記事の予告・告知

新しい記事を出した直後・出す前に出す。

```
今日 19 時に新記事を公開します。
タイトル：〇〇

——————
□ 〇〇とは
□ 〇〇の落とし穴
□ 〇〇の手順

予告を見ておきたい方はぜひ購読してください 👇
[https://...]
```

### 2. 軽い気づき・観察

日常で見つけた小さなネタ。本気のエッセイ未満。

```
今日気づいたんだけど、〇〇って実は△△と同じ構造してる。
だから□□が効くんだ、きっと。
```

### 3. 引用 + コメント

他人の Substack / X 投稿 / 記事に対する短い反応。

```
これすごい。
[URL]
〇〇の指摘がほんとに刺さる。
```

### 4. 質問を投げかける

読者からの反応を引き出す。

```
今 Substack で発信を始めるとしたら、最初の記事は何にする？
回答ぜひ ↓
```

### 5. リサイクル（過去記事の切り出し）

過去記事の良いフレーズや小見出しを Notes 化。新規フォロワーは過去を読んでいない。

```
3 ヶ月前に書いた記事から：

「〇〇は△△ではなく、□□だ」

[元記事 URL]
```

### 6. 相互フォローの呼びかけ（自分主催 or 参加）

```
Substack 始めたばかりの人、つながりませんか？

リプ（自己紹介＋発信テーマ）+ リスタックで、相互フォローしましょう 🙌

リプしてくれた方を片っ端からフォローします。
```

## 投稿の頻度（推奨）

- 平日 3〜5 本ペース
- 1 日 5 本以上はフォロワーへの通知が多すぎて逆効果

## やらないこと

- ❌ ハッシュタグの羅列（X 文化を持ち込まない）
- ❌ 全 Note が記事の宣伝（割合は 1 / 4 くらい）
- ❌ ネガティブな批判だけの Note（炎上リスク）
- ❌ 同じ趣旨の Note を短期間に連投

## ワークフロー（ユーザーから「Notes 出して」と頼まれたとき）

1. **目的を聞く**：告知 / 気づき / 引用 / 質問 / リサイクル のどれか
2. **本文ドラフトを提示**してユーザーに合意を取る
3. ユーザー OK で `mcp__substack-mcp__post_note(text=...)` を呼ぶ
4. 戻り値の `url` をユーザーに伝える

「下書きにしたい」「公開前に見たい」と言われた場合は、現状の Substack には Note の下書き API がないため、ユーザーが Web UI で書く必要がある旨を案内する。
