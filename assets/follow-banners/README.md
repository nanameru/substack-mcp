# 太陽の固定フォローバナー

承認済みのキャラクターを使った固定アセット。毎回生成し直さず、`manifest.json` のCDN URLを記事へ埋め込む。原本PNGと生成プロンプトもこのフォルダに保存する。

## 選択規則

- ランダム候補は `01-reading`（読書）、`02-meeting`（打ち合わせ）、`03-cafe`（カフェ）、`04-travel`（旅行）の4枚。
- `00-developer` は採用済み原本として保管するが、現在の抽選対象には含めない。
- 新規記事ごとに4枚から等確率で1枚選ぶ。同じ画像の連続選択は許容し、テーマによる選別や順番交代に置き換えない。
- 選択した画像IDとURLを記事の `post_id` とともに実行記録へ残す。再試行時はその記録を再利用し、引き直さない。
- 同じ記事内では同じバナーを使う。公開ページの閲覧ごとに切り替える機能ではない。
- 下記の抽選例は新規記事用。既存記事は記録済みの選択を使う。乱数実行機能が使えない環境では、その制約を報告し実行済みと偽らない。

```python
import json
import secrets
from pathlib import Path

manifest = json.loads(Path("assets/follow-banners/manifest.json").read_text())
selected_id = secrets.choice(manifest["candidates"])
selected = next(a for a in manifest["assets"] if a["id"] == selected_id)
print(selected["id"], selected["url"])
```

## 配置

記事の導入直後に画像を入れ、直下と記事末尾へ `[Xでフォローする](https://x.com/taiyo_ai_gakuse)` を置く。画像内の文字自体はリンクではない。リンクを太字記法で包まない（変換崩れ防止）。本人Substackの購読リンクは別途維持する。

サムネイルや本文図解とは別のアセットであり、記事のカバーには設定しない。公開前に画像URLとフォロー先が正しく保存されていることを確認する。CDNが取得できない場合は、無断で再生成せず下書きと不足理由を残す。

## 手動検証（TC-001 / Issue #12）

1. 5枚のPNGが読み込めること、1983×793であること、SHA256がマニフェストと一致することを確認する。
2. ランダム候補が4枚のみで重複しないことを確認する。
3. 4枚のCDN URLが200かつ画像として読み込めることを確認する。
4. 抽選例の実行結果が候補内であることを確認する（短い試行の出現頻度から等確率性を証明しない）。
5. 週次タスクを保存後に開き直し、4枚のURLと一度だけ選択する規則が残っていることを確認する。

画像の人物・文字・場面は生成後に目視確認済み。生成方法はbuilt-in image_gen。元写真や認証情報はこのリポジトリに含めない。
